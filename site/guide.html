04 / HOW IT WORKS

Temporary claims.
Durable truth.

A short tour of how Seatlock moves a seat from the waiting room to an auditable booking.

01 / JOINA queue-enabled show assigns each user a stable FIFO token. The Redis admitter grants access at the show's configured rate.
02 / HOLDThe owner gets a five-minute Redis hold. A Lua script checks admission, rate, seat ownership, and the six-seat limit atomically.
03 / CONFIRMPostgres commits bookings and pending payment intents together. A partial unique index prevents a second active booking for a seat.
04 / SETTLEA signed provider event makes the booking paid or cancelled. Replayed event IDs have no side effects; cleanup cancels stale unpaid bookings.
WHO OWNS WHICH STATE?TWO STORES · CLEAR BOUNDARIES

REDIS · SHORT-LIVED COORDINATION

  • Seat holds with 300-second expiry
  • Per-user held-seat membership
  • FIFO queue and admission tokens
  • Atomic Lua token buckets
  • Owner-bound compare-and-delete

POSTGRES · DURABLE RECORDS

  • Events, shows, and seats
  • Confirmed, paid, and cancelled bookings
  • Pending intents and provider webhook events
  • Partial unique index for active seat occupancy
  • Row-locked, multi-worker cleanup
INVARIANTS TO KEEP INTACTSAFETY FIRST

ONE ACTIVE BOOKING PER SEAT

Redis holds reduce contention, but the database unique index is the final arbiter. Cancelled history remains while the seat becomes available again.

ONLY THE OWNER RELEASES

The compare and delete happen inside Lua. An old owner cannot delete a new hold after their original TTL expires.

ONE EFFECT PER PROVIDER EVENT

Provider event IDs are unique. Event insertion and booking transition share a transaction that locks the booking row.

WORKERS CLAIM DISJOINT ROWS

`FOR UPDATE SKIP LOCKED` lets cleanup workers cancel separate batches without duplicating work or waiting on a claimed row.
